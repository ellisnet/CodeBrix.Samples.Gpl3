Manuals shipped with Fresco.Brix
===============================

WHAT IS HERE

  Nine PDF manuals, 3,368 pages, engraved and typeset by CodeBrix.LilyPort
  itself. They are what Help > LilyPort Documentation shows, and they are the
  only documentation the application carries about the music language. Every
  engraved example in them is vector content with real text (since the
  re-render of 2026-08-26), so it stays sharp at any zoom and its words can
  be selected and searched in any PDF reader.

  Every one was produced by tools/manuals, which drives LilyPort's own
  tools/Lily.Docs. See that tool's README.txt for how to regenerate them and
  for the measured figures. MANIFEST.txt beside this file records each PDF's
  page count, size and sha256.

    internals.pdf        LilyPond Internals Reference       1266 pages
    essay.pdf            Essay on automated music engraving   63 pages

THE LICENCE, AND WHY THIS FOLDER IS SEPARATE

  These are LilyPond's own manuals, under the GNU Free Documentation License,
  version 1.3 or later, with NO Invariant Sections, NO Front-Cover Texts and
  NO Back-Cover Texts. Copyright (C) 1996--2026 the LilyPond authors.

  The GNU FDL is NOT a software licence and is NOT GPL-compatible in either
  direction. Fresco.Brix is conveyed GPL-3.0-only (ruling FR1). The two live
  together the way GPLv3 section 5 allows separate works to: this folder holds
  DOCUMENTS and no source, COPYING.FDL travels with them as the licence itself
  requires, and the folder can be emptied without the application failing --
  Help > LilyPort Documentation then simply reports that no manuals are
  installed.

  THIRD-PARTY-NOTICES.txt section 9 in the Fresco.Brix root records the
  position; CodeBrix.LilyPort's own section 4 quotes upstream's licence
  statement verbatim.

WHY THEY ARE NOT MODIFIED, AND WHY THEIR TITLES SAY "LILYPOND"

  They are shipped exactly as rendered. A manual is a document with its own
  author, its own title page and its own licence; renaming one would be both a
  misrepresentation and an FDL modification. Ruling FR13 keeps "LilyPond" out
  of the application's CHROME and allows it wherever the point IS the lineage
  -- documentation is named in the ruling as one of those places, and a manual
  is documentation of the language, not a name for the engine.
