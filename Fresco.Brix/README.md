# Fresco.Brix

A music-notation text editor and engraving environment: write music in the
[LilyPond](https://lilypond.org) language, engrave it, read the score back, play it, and export
it — on Linux (X11, Wayland, framebuffer), macOS and Windows, from one codebase.

Fresco.Brix is a **CodeBrix.Platform application**. The deep tour — feature by feature, project
by project, package by package — is in the [repository README](../README.md#frescobrix); this
file is the short version for someone standing in this folder.

## Engraving, without an installation

Scores are engraved **in process** by
[CodeBrix.LilyPort](https://www.nuget.org/packages/CodeBrix.LilyPort.GplLicenseForever), a
managed port of LilyPond 2.27.2 that ships as a NuGet package. **No LilyPond installation is
used or required** — there is no external process, no `PATH` lookup, no version chooser and
nothing to download. The same package supplies `convert-ly` for updating older documents and the
MusicXML / ABC / MIDI importers.

The engine the user drives is LilyPort, and the application's menus, panels, buttons, tooltips
and status text name it as such. The *language* being edited is LilyPond, the nine bundled
manuals are LilyPond's own manuals under their own titles, and the lineage is stated plainly in
About and in the documentation — including here.

## Building and running

The plain **.NET 10 SDK** is the only prerequisite — no workloads, no native toolchain:

```
dotnet build Fresco.Brix.slnx -c Release
dotnet run --project src/Fresco.Brix.LinuxX11 -c Release
```

Substitute `LinuxWayland`, `LinuxFrameBuffer`, `MacOS`, `Win32Skia` or `WinWpfSkia` for another
head (the last two build on Windows only). A head takes file paths on the command line; if the
application is already running, the files open as **tabs in the running window** and the second
process exits.

The first engrave after a rebuild takes about 30 seconds while the engine's boot cache is built
for the new bits; every later start is about 0.4 seconds.

## Tests

The test projects are **Microsoft.Testing.Platform** executables — run the binaries:

```
tests/Fresco.Brix.Core.Tests/bin/Release/net10.0/Fresco.Brix.Core.Tests
tests/libs/Fresco.Brix.Ly.Tests/bin/Release/net10.0/Fresco.Brix.Ly.Tests
tests/libs/Fresco.Brix.MusicView.Tests/bin/Release/net10.0/Fresco.Brix.MusicView.Tests
```

⚠ A plain `dotnet test` against an MTP executable can report **"Zero tests ran"**; use the
binaries above, or `dotnet test --project <csproj>` / `--solution`.
